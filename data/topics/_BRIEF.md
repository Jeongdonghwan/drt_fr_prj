# 도로시펫 가맹 창업 — 주제 데이터 작성 지침 (2026-11-24)

키워드 페이지 4,000개를 조합할 **주제 데이터**를 쓴다. 한 주제 = JSON 파일 하나(`data/topics/<id>.json`).
조합기가 `{업종} {주제}`(예: "펫샵창업 허가 절차"), `{지역} {업종} {주제}`(예: "부산 애견샵창업 상권 분석") 페이지를 만들고,
지역 페이지("해운대구 펫샵창업")는 여러 주제의 절을 하나씩 뽑아 쓴다. 그래서 **모든 문단은 그것만 떼어 읽어도 말이 되어야 한다.**

## 먼저 읽을 것 (사실 근거 — 이것 밖의 사실을 만들지 않는다)
- `lib/site.ts` — 공식 가맹 페이지 문구(핵심 경쟁력 FR_CORE, 왜 도로시펫 FR_WHY, 11단계 FR_STEPS, 운영 철학 FR_MOTTO, 지점 BRANCHES, 연락처)
- `lib/compose-fr.ts` 의 TOPICS 12개·MARKET·steps 설명, `lib/article-fr.ts` — 이미 쓰인 표현(같은 문장을 베끼지 말고 사실만 가져온다)
- `SITE.md`, `CLAUDE.md`

## 쓸 수 있는 사실
- 도로시펫 가맹: 실전 운영 노하우 교육, 오픈 전 교육·오픈 후 정기 점검·매월 프로모션, 인테리어 가이드, 점주 상생(정기 소통), 건강검진·병력·혈통 정보를 투명하게 보여 주는 분양 관리, 전문 켄넬·캐터리 공급망, 블로그·인스타그램·유튜브 마케팅을 본사가 기획·운영, 입지 분석으로 동일 상권 중복 가맹 제한, 상담·계약·사후관리 표준 매뉴얼, 본사 방문 상담 원칙(전화만으로 결정하지 않음, 부산본점 방문), 11단계(미팅 예약 → 방문 상담 → 가맹 신청 → 상권 분석·점포 개발 → 인허가 점검 → 점포 계약 → 실측·도면 협의 → 가맹 계약 → 인테리어 공사 → 점주 교육 → 오픈) — 정확한 단계 이름은 site.ts 를 따른다.
- 법: 동물을 판매하는 영업은 동물보호법에 따라 지자체(시·군·구)의 **동물판매업 허가**가 필요하다. 시설 기준을 맞춰야 하므로 점포 계약 전에 확인한다. (조문 번호·시설 치수·수수료·처리 기간·과태료 금액 같은 세부 숫자는 쓰지 않는다.)
- 시장: 인건비·운영비 상승, 키오스크·무인화, 플랫폼 수수료 — site.ts/compose-fr.ts 에 있는 범위의 일반 서술만.
- 창업 일반 상식 수준의 서술(임대차 계약 전 용도·시설 확인, 상담 전에 후보 지역·점포 크기·운영 가능 시간 정리 등)은 써도 된다. 단 "~해야 합니다"식 단정 대신 "~부터 확인합니다", "~인 경우가 많습니다".

## 절대 쓰지 않는 것
- 금액·비율·기간·매출·수익·회수 기간·평수·가맹점 수·통계·순위 등 **근거 없는 숫자 전부** ("11단계"와 연락처만 예외). 비용은 "점포 크기·입지·인테리어 범위에 따라 달라 본사 상담에서 항목별로 안내"까지만.
- 지역 인구·반려동물 수·상권 이름 등 지역 사실. (지역은 `{short}` 자리표시자로만 들어간다.)
- 분양 절차·홈딜리버리·미용·호텔 같은 매장 손님용 운영 안내, 견종 설명.
- 타 브랜드 비교·비방, '최고·1위·보장·무조건·완벽·획기적', "~하신가요?", "지금 바로", 이모지, 마크다운 강조.
- 수익이 난다는 암시("안정적인 수익", "고수익"). '안정적으로 운영'까지는 가능.

## 자리표시자 (조합기가 채운다)
- `{L}` 업종 표기(예: 펫샵 창업, 애견 분양샵 창업, 반려동물 프랜차이즈) — 조사가 붙으면 `{L:을}` `{L:은}` `{L:이}` `{L:과}` `{L:으로}` 처럼 쓴다(받침에 맞게 을/를·은/는·이/가·과/와·으로/로 자동 선택).
- `{short}` 지역 짧은 이름(예: 수원, 해운대구, 전국) — 조사는 `{short:은}` 등 같은 방식. `{where}` = "수원에서" 또는 "어느 지역에서든"(문장 맨 앞이나 중간에 부사어로).
- `{BRAND}` 도로시펫, `{PHONE}` 상담 전화.
- 문단마다 `{L}` 또는 `{short}`/`{where}` 가 **최소 1번, 많아도 3번**. 지역 없는 페이지에서 `{short}`="전국", `{where}`="어느 지역에서든" 으로 바뀌어도 어색하지 않게 쓴다("{short} 점포"→"전국 점포"는 어색하므로 `{where}` 를 주로 쓰고 `{short}` 는 "{short} 예비 점주님", "{short} 가맹점" 같은 자리에만).

## 파일 형식 (JSON, UTF-8, 주석 없음)
```json
{
  "id": "license",
  "name": "허가 절차",
  "h1sub": ["동물판매업 허가를 점포 계약 전에 보는 이유", "..."],
  "lead": ["...", "..."],
  "summary": ["...", "..."],
  "facts": [["필요한 허가", "동물판매업 허가(동물보호법)"], ["...", "..."], ["...", "..."], ["...", "..."]],
  "sections": [
    { "sub": ["허가 주체와 신청 시점", "누가 언제 신청하나"], "p": ["문단 벌1", "문단 벌2", "문단 벌3"] }
  ],
  "faq": [{ "q": "...", "a": "..." }]
}
```
- `id`·`name` 은 아래 배정표 그대로.
- `h1sub` 3개: h1 키워드 뒤에 붙는 수식어, 12~24자, 자리표시자 없이. 예) 키워드 "펫샵창업 허가 절차" + "점포 계약 전에 확인할 것".
- `lead` 2개: h1 아래 설명 한 문장, 60~95자, `{L}` 포함.
- `summary` 2개: "핵심 요약" 상자 글, 각 3~4문장 170~220자. 결론부터. `{L}` 1~2번.
- `facts` 4개: [라벨(2~7자), 값(8~28자)] — 요약 상자 정보 칸. 자리표시자 없이, 근거 있는 사실만.
- `sections` **7개**: 절마다 `sub` 2개(세부 주제 문구 8~22자, 자리표시자 없이 — 조합기가 "{키워드}: {sub}" 로 h2 를 만든다) + `p` **3벌**. 한 벌 = **한 문단 220~270자**(공백 포함), 4~6문장이 이어지는 글. 세 벌은 같은 세부 주제를 **다른 관점·다른 문장**으로 쓴다(어순만 바꾼 것 금지 — 벌끼리 같은 문장 0개). 걱정 하나에 답 하나, 예비 점주가 실제로 묻는 것에 답한다. 목록·번호·줄바꿈 없이.
- `faq` 5개: 질문은 사람이 실제로 묻는 말(18~40자), 답은 첫 단어가 결론이고 60~130자. 질문에 `{L}` 또는 `{short}` 가 들어가도 된다(5개 중 2~3개).

## 품질
- 주제마다 절 7개는 서로 다른 세부 주제. 다른 주제 파일과 내용이 겹치지 않게 그 주제에만 집중(예: '허가 절차'는 허가 이야기, 마케팅 이야기를 길게 하지 않는다).
- 사람이 쓴 안내글 어조(합니다체). 브랜드명을 지워도 말이 되는 빈 문장 금지.
- 다 쓴 뒤 `python -I scripts/check_topics.py data/topics/<id>.json ...` 로 검사하고 오류 0이 될 때까지 고친다.
